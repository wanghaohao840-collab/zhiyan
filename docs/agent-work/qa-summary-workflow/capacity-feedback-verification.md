# 联合总结容量不足反馈

当最终汇总的最少必要内容超出模型输入容量，或每篇文档都因输入容量不足而失败时，后台写入 `QA_SUMMARY_CONTEXT_CAPACITY`。摘要任务和失败消息均保存该状态。页面提示用更少或更短的文档新建对话，再生成摘要。同一失败消息的原样重试请求会被拒绝。

逐篇错误混有瞬时故障时，任务继续走已有自动重试。部分文档摘要仍可用时，继续尝试汇总并列出未纳入的文档。配置错误沿用通用失败。容量拒绝在发出下一次模型请求之前完成，日志只记录固定原因。

## 验证结果

- 119 项后端测试通过。两种执行方式均覆盖最终汇总容量不足、所有逐篇超容量、容量与瞬时或未知故障混合、部分成功和配置错误。实际后台任务写入临时 SQLite，接口测试核对了任务和消息返回的状态及重试拒绝。
- 22 项前端测试和应用构建通过。Chromium 分别在 1440×1024 和 390×844 测试失败提示、新建对话入口及已有的摘要重试流程。浏览器使用隔离服务、临时 SQLite 和模型替身。

## Neon 规划回执

基准 `9a925f0`，模型 `gemini-4-neon-high`，会话 `230b2d01-d238-40e0-8830-7ddd337263cb`。两个授权文件各读取一次，返回 `SUCCESS`。

Neon 建议沿现有错误字段传递固定码，只在明确的汇总拒绝或所有逐篇都超容量时识别为容量错误。Codex 用这条规则保留混合故障的处理优先级，并将单篇文档恢复时也能执行的“换用更短文档”加入页面提示。
