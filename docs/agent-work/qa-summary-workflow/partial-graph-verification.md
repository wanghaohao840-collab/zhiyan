# 部分文档失败后的图谱引用验收

若部分文档的逐篇摘要失败，最终汇总只使用成功文档的摘要和各自的引用。工作流会舍弃基于原始文档全集查询的共享图谱，原因是实体名称等聚合字段可能来自失败文档。输出保留未纳入文档的提示。两篇中一篇失败、三篇中一篇失败时，均可继续汇总成功文档。跨文档图谱查询仍只执行一次。全部成功时继续使用原共享实体和引用编号。

## 验证结果

- 修复前，顺序执行和 LangGraph 都会把合成案例中失败文档参与的共享实体放入最终模型输入及引用。新增测试先复现这一问题，再验证两条路径下的两篇、三篇及图谱必选模式共六种情形。
- 项目 Python 环境运行了多文档工具、数据后端契约、回答转换、任务执行和 Neo4j 存储测试，121 项通过。另通过实际 `RagQaAnswerEngine` 检查了两条路径的来源转换。全部成功时共享引用编号和锚定文档均与原规则一致。部分成功时，转换后的文本和图谱引用都来自成功文档。

## Neon 规划回执

基准 `0161239`，模型 `gemini-4-neon-high`，会话 `cf19fcc4-b4cc-48d3-8bda-c38ffbd233e2`。两个授权文件各读取一次，返回 `SUCCESS`。

Neon 比较了舍弃共享图谱、筛选现有共享成员和重新查询成功范围。采用第一种做法，在 `collect` 阶段清除共享图谱，供最终提示词与结构化引用共同使用。局部筛选无法保证聚合属性的来源，重新查询会增加一次图谱调用。Codex 核对了 Neo4j 的实体名称取值、两路状态覆盖方式和 `graph_documents` 的仓库内使用位置。汇总元数据现在也记录实际成功的文档。
