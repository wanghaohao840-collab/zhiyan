# 多文档联合总结工作流

打开应用进程的环境变量 `ZHIYAN_MULTI_SUMMARY_WORKFLOW=langgraph` 后，产品端后台任务会用 LangGraph 处理选择了至少两篇文档的联合总结。这个开关默认关闭。产品问答入口需按现有配置启用。部署环境应安装当前 `requirements.txt` 中的依赖。进程重启后读取开关，清除该变量并重启即可回到顺序执行。

工作流按准备范围和图谱上下文、并发逐篇摘要、收集结果、生成联合总结四个阶段推进。文档采样限制在会话选中的范围内，同时最多处理三篇。两条执行路径共享采样、摘要缓存、上下文预算和引用格式。部分失败时，返回可用文档的总结，并在结果里列出未纳入的文档标识。全部失败时，由已有任务系统根据错误类型决定是否重试。

开关开启时，大模型调用每阶段只尝试一次。工作流状态只保存在本次运行的内存中。任务进度、取消、重试、答案和来源依旧由现有任务数据库管理。失去租约意味着当前工作进程失去继续处理该任务的资格。

## 查看运行情况

设 `hello_agents.tools.builtin.rag_summary_workflow` 日志记录器为 `INFO` 并配置输出。用后台任务返回的 `job_id` 查找日志，按 `attempt` 区分领取次数，再用 `run_id` 聚合本次四个阶段。顺序执行、LangGraph 和调试降级路径分别记录 `direct`、`langgraph` 和 `langgraph_debug_fallback`。日志还记录耗时、文档计数、缓存命中和裁剪状态。模型未正常结束时只记录固定分类，逐篇异常按类别计数。任务最终状态以后台任务接口为准。

试点关闭 LangSmith 外部追踪。进程若启用了 LangChain 全局调试输出，该次调用改走相同的顺序执行阶段，以免框架调试输出文档内容。

## 验收边界

测试使用真实的 RAG 工具、LangGraph 和临时 SQLite 任务库，检索后端、图谱服务与模型传输使用可控替身。现有进度事件负责续租和发现取消，进行中的模型或检索调用会在返回后收尾。单次调用耗时超过任务租约时，接管可能带来重复计算。测试覆盖新工作进程接管并提交后，旧工作进程的迟到结果被拒绝。SQLite 等待写锁期间跨过租约到期时间的处理沿用现有仓库逻辑。
