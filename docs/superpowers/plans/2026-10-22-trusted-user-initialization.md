**Goal:** Give operations a local, explicit way to create a genuinely new account with complete trusted empty History/Memory and RAG/episode baselines, while keeping public registration closed and isolated import admission gated by the existing allowlist and `ordinary_ready`.

**Architecture:** Static resource validation and a PostgreSQL read-only operation lookup come first; an already completed matching operation returns from immutable historical proof even if S3 or Qdrant is currently down. Only a new operation hashes the password and read-only probes the existing isolated S3 bucket and Qdrant collections. One short READ COMMITTED PostgreSQL transaction then creates the user, two v1 snapshots, two zero-point published generation/head/receipt pairs, a History document witness, and an immutable completion credential. A caller-supplied operation UUID makes ambiguous commits and retries read-only verifiable; no durable preparing state, cross-store writes, claim system, or historical-user repair is introduced.

**Tech Stack:** Python, psycopg/PostgreSQL/Alembic, S3 and Qdrant read-only probes, pytest; Windows PowerShell with `D:\python_self_agent\venv\Scripts\python.exe`.
